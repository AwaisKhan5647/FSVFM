────────────────────────────────────────────────────────────────────────────────
CHANGES MADE TO TRAINING PIPELINE
────────────────────────────────────────────────────────────────────────────────

1. BALANCED BATCH SAMPLING (fsvfm/util/composite_dataset.py)
   ─────────────────────────────────────────────────────────
   Added DistributedBalancedSampler — a custom DDP-aware sampler that guarantees
   every single batch on every GPU contains exactly 50% real and 50% fake frames.
   This is NOT the same as dataset-level balancing (which only balances overall);
   this ensures the model never sees an imbalanced gradient signal within a batch.

   Mechanism:
     • Separates all indices into real_indices[] and fake_indices[]
     • Each rank owns non-overlapping half-blocks of size (batch_size//2)
     • Emits indices in pattern: [32 real, 32 fake, 32 real, 32 fake, ...]
     • DataLoader picks up each consecutive 64 → always 32 real + 32 fake
     • Minority class is oversampled (tiles) to match the majority class size
     • set_epoch(epoch) re-shuffles each epoch while preserving balance

   Also added build_from_txt_pair() — builds dataset directly from two separate
   path-list txt files (one path per line, no label column needed).

2. BATCH SIZE INCREASED: 32 → 64 per GPU
   ─────────────────────────────────────
   2× RTX 6000 Ada (51 GB each) can comfortably run ViT-L/16 at 224×224 with
   batch_size=64 per GPU.
   Effective batch = 64 GPU-0 + 64 GPU-1 = 128 total.
   Per batch: 32 real + 32 fake on each GPU = 64 real + 64 fake globally.

3. PER-EPOCH TEST EVALUATION (engine_finetune.py + train_composite.py)
   ──────────────────────────────────────────────────────────────────────
   Old evaluate() was BROKEN: it computed AUC per-batch and then averaged the
   per-batch AUCs — mathematically wrong because AUC is a global rank metric.

   New evaluate_full():
     • Collects ALL predictions and labels across the full test set
     • Gathers across all DDP ranks via dist.all_gather_object
     • Computes metrics on the complete, globally-aggregated prediction array
     • Returns: Accuracy, AUC, Real_Accuracy, Fake_Accuracy, Loss

   Called after every epoch. Best checkpoints tracked on three criteria:
     checkpoint-best_auc.pth   — highest AUC on test set
     checkpoint-best_acc.pth   — highest Accuracy on test set
     checkpoint-min_loss.pth   — lowest test loss

4. METRICS: result.txt written after every epoch
   ───────────────────────────────────────────────
   File: experiments/<run_name>/result.txt
   Format per epoch:
     Epoch  0 | Accuracy=XX.XX% | AUC=XX.XX% | Real_Accuracy=XX.XX% | Fake_Accuracy=XX.XX% | Loss=X.XXXX
     Epoch  1 | ...
     ...
     Epoch -1 [FINAL_BEST] | ...   ← written at end of training

   Definitions:
     Accuracy      = (TP + TN) / (TP + TN + FP + FN)  overall correct predictions
     AUC           = Area Under ROC Curve (0–100%)
     Real_Accuracy = TN / (TN + FP)  — how well the model identifies real frames
     Fake_Accuracy = TP / (TP + FN)  — how well the model identifies fake frames

5. NEW TXT-FILE DATASET INTERFACE
   ────────────────────────────────
   Training now accepts separate real/fake path-list txt files directly.
   New args:
     --real_train_txt  /path/to/0_real_train.txt   (one abs path per line)
     --fake_train_txt  /path/to/1_fake_train.txt
     --real_test_txt   /path/to/0_real_test.txt
     --fake_test_txt   /path/to/1_fake_test.txt

   If txt files are not provided, falls back to directory-based --train_root mode.

6. PROGRESS.TXT + TENSORBOARD logging
   ─────────────────────────────────────
   At training start: dataset statistics (total/real/fake counts, roots, GPU info,
   batch config) written here.
   Each epoch: one-line summary appended here.
   TensorBoard: test/auc, test/accuracy, test/real_accuracy, test/fake_accuracy,
                test/loss, train/loss all logged per epoch.
